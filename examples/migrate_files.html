# Merlin Language — Data Migration in One Pipeline > **Zero backend. Zero Python. One URL. No compilation.** ## The Problem Example : You have the JSON file background.json in this format: ```json { "BACKGROUND_NAME": "marble_arco_iris", "DESCRIPTION": "Marble - Arco Iris", "CSS_PLUS": "body { ... }", "IMAGE": "background/marble_arco_iris.webp", "SHADOW_COLOR": "" } ``` You need to convert it — renaming the key 'BACKGROUND_NAME' to `TITLE`, adding a sequential `ID`, and dropping the old key field. Then, across **6 different config files**, each with a different key name --- ## The Merlin Solution ``` %%%% // PARAM1 - Name of the Json File without .json // PARAM2 - Name of the key to become 'TITLE' $MODEL = PARAM1 | LOWER $KEY_NAME = PARAM2 | LOWER #REGS[] = JSON.FIND_ALL(JSON_PATH.$$MODEL) REGS | ADD_FIELD(@ID = IDX 1 +) | ADD_FIELD($TITULO = ITEM.$$KEY_NAME) | DELETE_FIELD(KEY_NAME) | ATUALIZE JSON.WRITE(JSON_PATH.$$MODEL, REGS) %%%% Migration complete — {{{{ REGS.LEN() }}}} records updated ``` **Called via URL — no deployment, no terminal:** ``` https://your-server.com/your-slug/migrate_files/background/name_background https://your-server.com/your-slug/migrate_files/configs/name_configs https://your-server.com/your-slug/migrate_files/themes/name_theme ``` `PARAM1` = model name → resolves to the correct JSON file path `PARAM2` = the old key field name to rename → becomes `TITLE` All 6 files migrated with the **same script**, just different URL parameters. --- ## Result **Before:** ```json { "BACKGROUND_NAME": "marble_arco_iris", "DESCRIPTION": "Marble - Arco Iris", "CSS_PLUS": "body { ... }", "IMAGE": "background/marble_arco_iris.webp", "SHADOW_COLOR": "" } ``` **After:** ```json { "ID": "1", "TITLE": "marble_arco_iris", "DESCRIPTION": "Marble - Arco Iris", "CSS_PLUS": "body { ... }", "IMAGE": "background/marble_arco_iris.webp", "SHADOW_COLOR": "" } ``` --- ## Equivalent Python Script The same task in Python requires a dedicated script, file handling, argument parsing, and manual execution in a terminal: ```python import json import sys def converter(input_path, output_path, key_name): with open(input_path, 'r', encoding='utf-8') as f: data = json.load(f) result = [] for i, item in enumerate(data, start=1): fields = item.get("fields", {}) new_item = { "ID": str(i), "TITLE": item.get(key_name, ""), "CSS_PLUS": fields.get("css_adicional", "").replace("\r\n", "\n"), "SHADOW_COLOR": fields.get("shadow_color", ""), "IMAGE": fields.get("imagem", ""), } result.append(new_item) with open(output_path, 'w', encoding='utf-8') as f: json.dump(result, f, ensure_ascii=False, indent=2) print(f"✅ Converted {len(result)} records → {output_path}") if __name__ == "__main__": input_path = sys.argv[1] if len(sys.argv) > 1 else "background_django.json" output_path = sys.argv[2] if len(sys.argv) > 2 else "background.json" key_name = sys.argv[3] if len(sys.argv) > 3 else "nome_background" converter(input_path, output_path, key_name) ``` **Then run it manually only for the background.json file:** ```bash python converter.py background_django.json background.json nome_background ``` --- ## Side-by-Side Comparison | | **Merlin** | **Python** | |---|---|---| | Lines of code | 7 | 30+ | | Files to create | 1 template | 1 script per model | | Execution | Browser URL | Terminal + Python installed | | Reusable for all models | ✅ URL parameters | ❌ Modify script each time | | Deploy needed | ❌ None | ✅ Script must be on server | | Result visible instantly | ✅ In browser | ❌ Check output file manually | --- ## How the Pipeline Works ``` REGS | ADD_FIELD(@ID = IDX 1 +) ``` Adds a sequential numeric `ID` to every record, starting at 1. ``` | ADD_FIELD($TITLE = ITEM.$$KEY_NAME) ``` Adds a `TITLE` field with the value from the old key field (resolved dynamically from the URL parameter). ``` | DELETE_FIELD(KEY_NAME) ``` Removes the old key field — the one being replaced by `TITLE`. ``` | ATUALIZA ``` Commits the changes back to the `REGS` vector in memory. ``` JSON.WRITE(JSON_PATH.$$MODEL, REGS) ``` Persists the updated records to the correct JSON file on disk. --- ## Key Concept: Generic Scripts via URL Parameters In Merlin, any template can act as a script. The generic routing system resolves `PARAM1` and `PARAM2` directly from the URL path: ``` /slug/script_name/PARAM1/PARAM2 ``` This means one template handles infinite variations — no code changes, no redeployment, no terminal access required.
